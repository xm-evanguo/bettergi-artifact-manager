# 数据与规则

## 库存快照

标准格式为 `schemaVersion: 1`，顶层含 `scan` 和 `artifacts`，完整例子见 [虚构示例](../repo/js/ArtifactManager/data/demo-snapshot.json)。

`scan` 至少需要 `id`、`total`、`complete`、`verified` 和 `issues`；可补充 `capacity`、游戏版本、分辨率和时间。`complete` 表示扫描覆盖完整，`verified` 表示已核对该扫描；仅在没有漏扫、重复和误读的证据下才能设为 `true`，不能只为开启清理而修改标记。

每件记录包含：

| 字段 | 含义 |
| --- | --- |
| `id` | 本次扫描中唯一的逐件编号，不能按属性哈希去重 |
| `name`、`set` | 名称和完整套装名 |
| `slot` | 0 花、1 羽、2 沙、3 杯、4 冠 |
| `rarity`、`level` | 明确识别的星级与等级；未知用 null |
| `main` | `{ "key": "atk", "value": 46.6 }` |
| `subs` | `{ "key": "cpct", "value": 3.9, "active": true }` 的数组 |
| `locked` | true / false；未确认用 null |
| `equippedBy` | 已确认未穿戴用空字符串，已穿戴用角色名，未知用 null |
| `location` | 本次扫描的页、行、列或序号；排序、强化后不能沿用 |
| `rawOcr`、`issues` | 原始文字和异常；至少保留定位或原始记录 |

属性键：`hp/atk/def` 是百分比，`hpPlus/atkPlus/defPlus` 是固定数值，`mastery` 精通、`recharge` 充能、`cpct` 暴击率、`cdmg` 暴击伤害、`heal` 治疗加成；元素主词条用 `pyro/hydro/cryo/electro/anemo/geo/dendro`，物伤为 `phy`。

百分比数值为百分数：46.6% 填 46.6，而非 0.466。`active: false` 表示已显示但未激活的第四条，不计入当前分数。读到未知第四条时不能编造内容。

OCRArtifacts 的数组可直接导入，但上游 `star` 来自套装推断，本项目不信任它；缺失的锁定和穿戴状态也不补成 false。因此这类导入默认只能帮助查看与复核，不能直接清理。

数值检查只排除一部分明显错误，包括主副词条上限、五星词条数量及词条总量与等级不符；它不能证明 OCR 正确。当前保存的是文字和坐标，没有物品截图。

## 角色配置

`characters` 是 `{ "name": "角色名", "priority": "main" }` 数组，备用用 `reserve`。不在 miao-plugin 角色权重表中的名字会被明确列为缺规则，不会自动套用通用双暴权重。`rosterConfirmed: true` 表示用户已确认本次整理覆盖的角色和玩法范围。

`rules` 以角色名为键，每个角色支持多个玩法。规则形状如下，字段需根据实际玩法核对：

```json
{
  "id": "实际玩法名称",
  "sets": ["游戏中的完整套装名称"],
  "mainStats": {
    "0": ["hpPlus"],
    "1": ["atkPlus"],
    "2": ["recharge", "atk"],
    "3": ["electro", "atk"],
    "4": ["cpct", "cdmg"]
  },
  "weights": {},
  "reviewed": false,
  "source": "逐篇攻略链接",
  "version": "该篇攻略实际适用版本及队伍假设"
}
```

上例只演示格式，不是任何角色的建议。默认使用 miao-plugin 的 `usefulAttr` 权重；`weights` 可明确覆盖 0 至 100 的权重。角色的 `options.elem` 可覆盖参考分使用的元素；参考分不计算武器、命座和角色专属规则。去留判断采用规则中的有效属性方向，不能假设参考分已代替充能门槛或完整配装计算。

`reservePerCharacter` 默认 2，是每种同套装、部位、主词条用途池给每个角色预留的数量，不代表最终装备分配。角色的多个玩法取需求并集，报告仅展示候选。`protectedIds` 是本次扫描中手工保护的编号列表；强化和重新扫描后需重新核对编号。

`targetFreeSlots` 是整理后目标空位数。已知容量时可计算当前与预计空位；数量不足则显示差额，不降低保留标准。容量未知时，报告按需要新增的空位显示目标差额。

## 判断方法

1. 锁定、穿戴、用户保护件先保留；识别未知项阻止清理。
2. 保留低星过渡件、稀缺功能主词条、有价值的散件和角色候选。
3. 每个角色分配独立保留额度，永久保留一批满级替代件，清理件不能互相充当替代件。
4. 只有同套装、部位、主词条中存在足量满级替代件，且各已配置用途的每项有效属性都不差，才考虑冗余清理。
5. 未满级物品只要仍能获得有效属性，就不按当前低分淘汰；已知四条无用属性不会虚构新词条，但仍需全部替代证据。

强化建议列下一检查点和继续、停止的人工判断条件。潜力上限使用最乐观的词条提升，不是期望收益或成功概率，也没有测算经验、摩拉预算。停止强化不等于立即废弃。
